Two parallel feature folders under `src/app/` (`universities`, `courses`) each follow the same Next.js App Router layout: a route `page.tsx` (server component) that declares metadata and wraps a content component in `AppLayoutWrapper`; an `[id]/page.tsx` server component that awaits params and renders a detail content component; `add/page.tsx` and `edit/[id]/page.tsx` for creation/editing; and a `components/` folder of client components marked with `'use client'`. Data fetching is split by resource: the courses list page fetches directly from Prisma via `@/lib/db` inside a server component and passes initial data through props wrapped in `Suspense`, while the universities list page uses a client-side `fetch('/api/universities')` call inside `UniversitiesContent`. Both features expose REST endpoints at `/api/universities/*` and `/api/courses/*` for CRUD, mutations, and bulk actions. UI state (search, filters, sort, pagination, view mode, selection) lives in local `useState` within the large `*Content` components, which are composed into smaller sub-components (e.g., `UniversityTable`, `UniversityGrid`, `SearchFilters`, `BulkActionBar`). Detail pages render read-only breakdowns via `UniversityDetailContent` / `CourseDetailContent`, while edit/add flows use shared form building blocks (`BasicInfoCard`, `ContactCard`, `MediaCard`, `RequirementsCard`, `AccreditationCard`, `PartnershipCard`, `FormHeader`, `FormActions`, `UniversityForm`).
