Three sibling Next.js App Router route segments (`/payments`, `/expenses`, `/commission`), each following the same layout: a thin `page.tsx` server component that exports metadata and renders the feature's content inside the shared `AppLayoutWrapper`, delegating all interactivity to a `components/<Feature>Content.tsx` client component marked with `'use client'`. Each content component owns its own React state for data, filters, modals, and submit loading; it fetches data from dedicated REST endpoints (`/api/payments`, `/api/students`, `/api/expenses`, `/api/universities`, `/api/courses`) using `fetch` and posts new records back to those same endpoints. The commission page additionally paginates via a local `fetchAll` helper that loops over `?page=&perPage=100` responses and merges university/course rows into a unified table. UI is built entirely with Tailwind CSS classes and lucide-react icons, with user feedback delivered through `sonner` toasts. There is no shared state or cross-page communication — each segment is an independent vertical slice of the admin finance domain.
