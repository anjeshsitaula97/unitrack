The flow starts in `src/components/CheckoutModal.tsx`, a client component that reads plans and prices from `src/lib/pricing.ts` (NPR-denominated monthly/yearly plans with a 25% annual discount) and asks `/api/checkout/config` for per-gateway availability. On submit it POSTs to `/api/checkout/initiate`, which delegates to `src/lib/checkout/{esewa,connectips}.ts` to build signed gateway forms; the modal then POSTs those fields directly to the gateway's redirect URL. After payment, the gateway calls back into `src/app/api/checkout/esewa/{success,failure}` or `connectips/{success,failure}`, where the same library functions verify signatures and persist order state via the shared database layer. The `src/app/checkout/result/page.tsx` renders the post-payment confirmation page. This module therefore sits at the boundary between UI (modal), business logic (pricing + gateway clients), and routing (Next.js API routes), with all cross-cutting concerns (plan definitions, currency, gateway SDKs, reference generation) centralized under `src/lib/` so the routes stay thin.
