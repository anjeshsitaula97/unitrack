Built on Next.js App Router with a page/component split: each route (`applications/page.tsx`, `applications/[id]/page.tsx`, `applications/new/page.tsx`, `tasks/page.tsx`) is a thin server component that wraps its UI in `AppLayoutWrapper` and exports metadata. Client-side logic lives in `components/` subdirectories marked with the `"use client"` directive — `ApplicationsContent` (list, filter, paginate, delete), `ApplicationDetailContent` (detail view with Requirements/Student records/Workflow/Notes/Commission/Settings tabs, status updates, document upload, notes CRUD, workflow stage management), `ApplicationForm` (create new application via student/university/course selectors), and `WorkflowContent`/`VisaWorkflowDashboard` (country → visa type → task workflow). Data access is direct `fetch()` calls to REST endpoints under `/api/applications`, `/api/students`, `/api/courses`, `/api/tasks`, `/api/visa-types`, `/api/learning-hub/countries`, etc., with no shared data-fetching library. The detail page composes reusable status helpers from `@/lib/application-statuses`. Navigation between routes uses `next/navigation`'s `useRouter` and URL search params are kept in sync with the current country/visa view.
