Three sibling Next.js Route Handler pages (`chat/page.tsx`, `notifications/page.tsx`, `email/page.tsx`) each export a default React component wrapped in `AppLayoutWrapper` and declare page-level metadata (title/description). Each page delegates UI to a client-side content component marked with the `'use client'` directive: `ChatContent` (two-panel conversation list + message pane), `NotificationsContent` (list with mark-as-read/delete/clear actions), and `EmailContent` (compose form plus SMTP settings tab). All three components are pure client-side React that call backend endpoints via `fetch` or the shared `@/lib/fetch-client` helper (`api`, `safeJson`): chat uses `/api/chat/*`, notifications use `/api/notifications`, email uses `/api/email/send` and `/api/email-settings`. Polling is implemented with `setInterval` inside `useEffect` to keep rooms and messages fresh. There is no shared state between the three features — they are independent feature slices sharing only the layout wrapper and fetch utilities.
