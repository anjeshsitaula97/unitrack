Three Next.js Route Group pages under `src/app/` each act as thin route shells that render a shared `AppLayoutWrapper` and delegate UI to a page-specific content component: `dashboard/page.tsx` → `DashboardContent`, `admin-dashboard/page.tsx` → reused `DashboardContent`, and `settings/page.tsx` → `SettingsContent`. The dashboard is widget-driven: `DashboardContent` maintains a configurable widget registry (`WIDGET_LIBRARY`) and KPI list (`kpi-data.tsx`), renders charts via `next/dynamic` with `ssr: false` (charts are client-only), and persists layout/KPI visibility through `/api/dashboard-layout`. The settings module is a single large tabbed client component (`SettingsContent.tsx`) managing roles, permissions, localization, branches, qualifications, email SMTP, application statuses, and modules, all backed by REST endpoints under `/api/*`. A nested `settings/backups/page.tsx` implements an in-browser backup/restore flow: it defines a `DATA_SECTIONS` catalog mapping logical sections to Prisma table names, supports optional AES-256 encryption via password prompts, downloads JSON blobs from `/api/backup?tables=...`, and POSTs uploaded backups to `/api/restore`. All user-facing notifications go through `sonner` toasts and destructive actions use a shared `ConfirmDialog`.
