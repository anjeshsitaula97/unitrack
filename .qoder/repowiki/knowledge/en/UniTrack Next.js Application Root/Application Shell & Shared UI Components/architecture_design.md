The module is organized as a flat shell layer under `src/components/` with two small sub-packages: `ui/` for brand-agnostic primitives (`AppLogo`, `AppIcon`, `AppImage`) and `hr/` for HR-specific features (`CameraCapture`, `FaceVerificationModal`). `AppLayoutWrapper.tsx` is the entry point that fetches `/api/auth/me`, caches auth state in module-level variables (`cached`, `inFlight`), guards against unauthenticated sessions by redirecting to `/login`, and resolves role-based home routes via `getRoleHome`. It composes `AppLayout.tsx`, which renders `Sidebar`, wraps children in `ErrorBoundary`, mounts `GuidedTour`, and places a Sonner `Toaster`. Navigation is data-driven: `Sidebar.tsx` declares a single `navSections` array of `NavItem`/`NavSection` objects and filters them at runtime using `MODULES` and `getEnabledModuleIds` from `@/lib/modules`, so menu items are decoupled from rendering logic. Cross-cutting concerns are isolated in dedicated components: `ErrorBoundary` catches render errors, `GuidedTour` runs only when `user.isFirstLogin === true` and marks itself complete via PATCH to `/api/auth/tour-completed`, and notifications in both `Topbar` and `Sidebar` share an identical pattern of initial `fetch("/api/notifications")` followed by an `EventSource` subscription to `/api/notifications/stream` with id-based deduplication. Logout flows consistently call `/api/auth/logout`, then invoke `clearAuthCache()` from `AppLayoutWrapper` and `deactivateSession()` from `@/lib/client-session` before navigating to `/login`.
